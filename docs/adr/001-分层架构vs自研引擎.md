# ADR-001: 分层架构+桥接引擎 vs 自研引擎

> 日期：2026-05-18
> 状态：已决策
> 决策者：产品经理+主人

## 上下文

主人希望构建AI-First游戏创作平台，覆盖小游戏到3A。需要决定：是自研游戏引擎，还是分层架构+桥接现有引擎。

## 决策

**选择：分层架构+桥接现有引擎**

架构分三层：
1. **AI编排层（Forge Core）**——自建，核心价值
2. **逻辑/资产层（Script Forge/Asset Forge）**——自建，AI接口
3. **渲染运行时**——2D自建Light Runtime，3D桥接Godot/Unreal

## 理由

| 维度 | 自研引擎 | 分层+桥接 |
|------|---------|----------|
| 3A能力 | 需10年+，不现实 | 桥接Unreal即可 |
| 2D能力 | 可行 | 自建Light Runtime即可 |
| AI友好 | 从头设计最好 | 编排层AI友好，渲染层AI不需要关心 |
| 工作量 | 无底洞 | 可控，分阶段 |
| 核心价值 | 引擎本身 | AI创作能力 |
| 无限扩展 | 需要改引擎 | 注册扩展即可 |

**核心洞察**：我们的创新点不在引擎，在"AI怎么创作游戏"。引擎是管道不是水源。

## 后果

- 正面：可控交付、复用现有生态、AI编排层是真正护城河
- 负面：桥接层有适配成本、Godot/Unreal版本升级需跟进
- 风险：云渲染延迟——Phase 1不依赖，Phase 2/3再验证

## 关联

- 与OpenDAW的Extension Registry理念一致
- VCMix的YAML→渲染经验可复用
